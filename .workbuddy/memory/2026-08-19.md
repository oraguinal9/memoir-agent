### 深度测试发现并修复的 3 个问题
1. **parser 表头识别过宽**：用子串匹配（如含"内容"两字）会把纯文本误判为 CSV 表头；改为"≥2 个已知列才算表头"识别 + 纯文本逐行兜底（每行当作一条消息）
2. **API 真空 body 会 500**：所有 `await req.json()` 无保护 → 给 4 个 POST route 加 `.catch(() => ({}))`：import / interview / interview-complete / book-chapter
3. **无内容 JSON 的行为**：解析 0 条时合理返回 400+错误信息（不静默成功），测试断言对齐

### 关键设计决策（深度测试验证后）
- 相邻同发送者消息自动合并（"对方"连续发言合为一条）—— 纯文本兜底时也适用，避免冗余
- 重复"结束访谈整理"不产生重复事件（lib/extract.ts mock 去重按 title 前 8 字包含匹配）
- 章节用户编辑后"重新生成书稿"会被覆盖（当前实现每次 buildBook 重建）—— 这是已知行为，生成前会提示用户
